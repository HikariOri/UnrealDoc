2381 /*
2382 ========================================================================
2383 Here's how player movement prediction, replication and correction works in network games:
2384
2385 Every tick, the TickComponent() function is called. It figures out the acceleration and rotation change for the frame,
2386 and then calls PerformMovement() (for locally controlled Characters), or ReplicateMoveToServer() (if it's a network client).
2387
2388 ReplicateMoveToServer() saves the move (in the PendingMove list), calls PerformMovement(), and then replicates the move
2389 to the server by calling the replicated function ServerMove() - passing the movement parameters, the client's
2390 resultant position, and a timestamp.
2391
2392 ServerMove() is executed on the server. It decodes the movement parameters and causes the appropriate movement
2393 to occur. It then looks at the resulting position and if enough time has passed since the last response, or the
2394 position error is significant enough, the server calls ClientAdjustPosition(), a replicated function.
2395
2396 ClientAdjustPosition() is executed on the client. The client sets its position to the servers version of position,
2397 and sets the bUpdatePosition flag to true.
2398
2399 When TickComponent() is called on the client again, if bUpdatePosition is true, the client will call
2400 ClientUpdatePosition() before calling PerformMovement(). ClientUpdatePosition() replays all the moves in the pending
2401 move list which occurred after the timestamp of the move the server was adjusting.
2402 */
