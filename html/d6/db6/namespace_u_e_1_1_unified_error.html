详细描述

MIGRATION GUIDE

It is desirable for systems with their own existing error types to be compatible with FError so that callers can deal with only FError for error handling and propagation. e.g. if system HighLevelA calls functions in systems LowLevelB and LowLevelC, HighLevelA would like to define its functions to return FError and to be able to pass through errors from LowLevelB and LowLevelC through that function signature.

Existing systems which return their own error types and cannot easily be changed to return FError can provide compatibility with FError as follows:

  • Declare a new set of desired errors with the UE_DECLARE_ERROR macros. These errors may map 1:1 or 1:many to the existing error type, and should have fields to copy the details from the original error type into.
  • These errors can use an existing error enum as a parameter to the UE_DECLARE_ERROR macro as long as that enum can be cast to int32.
  • If the existing error enum declares an entry for a value of 0, that cannot be used with UE_DECLARE_ERROR.
