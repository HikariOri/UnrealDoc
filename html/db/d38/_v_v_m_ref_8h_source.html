200// There are different designs going on in regards to VNativeRef and VTransparentRef in the VM currently, ie:
201//
202// VTransparentRef --> We call `UnwrapTransparentRef` in several OpCodes (see LoadField as example) to unwrap these
203// and return the VCell it points to which allows us to directly mutate it which is our current impl of VCell 'deep mutability'.
204//
205// VNativeRef --> The `UnwrapTransparentRef` design does not work here, as we have no 'value' that can be directly passed around, and instead
206// we create a VNativeRef when loading out of a native object via VObject::LoadField/UVerseClasss::LoadField and rely on `Freeze` OpCodes
207// to unwrap them at the correct point.
208//
209// Long term, when we implement 'correct' deep mutability we will need to change from directly passing VCell's around to passing
210// Ref's around which should let us align these two approaches. But for now they are separate and there may be holes where the VNativeRef
211// returned by `LoadField` is not handled by a freeze before being passed to another OpCode and will most likely crash.
212template <typename SetType>
213VValue UnwrapTransparentRef(FAllocationContext Context, VValue Value, VTask* Task, SetType Set)
214{
215 AutoRTFM::UnreachableIfClosed("#jira SOL-8415");
216
217 if (VRef* TransparentRef = Value.ExtractTransparentRef())
218 {
219 if (Task && Task->AwaitPC)
220 {
221 TransparentRef->AddAwaitTask(Context, *Task);
222 }
223 return TransparentRef->Get(Context);
224 }
225 if (Task && Task->AwaitPC)
226 {
227 VRef& NewRef = VRef::New(Context, {});
228 NewRef.SetNonTransactionally(Context, Value);
229 NewRef.AddAwaitTask(Context, *Task);
230 Set(VValue::TransparentRef(NewRef));
231 }
232 return Value;
233}
