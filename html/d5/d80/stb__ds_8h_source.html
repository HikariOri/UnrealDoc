24 #define STBDS_NO_SHORT_NAMES
25
26 This flag needs to be set globally.
27
28 By default stb_ds exposes shorter function names that are not qualified
29 with the "stbds_" prefix. If these names conflict with the names in your
30 code, define this flag.
31
32 #define STBDS_SIPHASH_2_4
33
34 By default stb_ds.h hashes using a weaker variant of SipHash and a custom hash for
35 4- and 8-byte keys. On 64-bit platforms, you can define the above flag to force
36 stb_ds.h to use specification-compliant SipHash-2-4 for all keys. Doing so makes
37 hash table insertion about 20% slower on 4- and 8-byte keys, 5% slower on
38 64-byte keys, and 10% slower on 256-byte keys on my test computer.
39
40 #define STBDS_UNIT_TESTS
41
42 Defines a function stbds_unit_tests() that checks the functioning of the data structures.

44 Note that on older versions of gcc (e.g. 5.x.x) you may need to build with '-std=c++0x'
45 (or equivalentally '-std=c++11') when using anonymous structures as seen on the web
46 page or in STBDS_UNIT_TESTS.

55 Dynamic Arrays
56
57 Non-function interface:
58
59 Declare an empty dynamic array of type T
60 T* foo = NULL;
61
62 Access the i'th item of a dynamic array 'foo' of type T, T* foo:
63 foo[i]
64
65 Functions (actually macros)
66
67 arrfree:
68 void arrfree(T*);
69 Frees the array.
70
71 arrlen:
72 ptrdiff_t arrlen(T*);
73 Returns the number of elements in the array.
74
75 arrlenu:
76 size_t arrlenu(T*);
77 Returns the number of elements in the array as an unsigned type.
78
79 arrpop:
80 T arrpop(T* a)
81 Removes the final element of the array and returns it.
82
83 arrput:
84 T arrput(T* a, T b);
85 Appends the item b to the end of array a. Returns b.
86
87 arrins:
88 T arrins(T* a, int p, T b);
89 Inserts the item b into the middle of array a, into a[p],
90 moving the rest of the array over. Returns b.
91
92 arrinsn:
93 void arrins(T* a, int p, int n);
94 Inserts n uninitialized items into array a starting at a[p],
95 moving the rest of the array over.
96
97 arraddnptr:
98 T* arraddnptr(T* a, int n)
99 Appends n uninitialized items onto array at the end.
100 Returns a pointer to the first uninitialized item added.
101
102 arraddnindex:
103 size_t arraddnindex(T* a, int n)
104 Appends n uninitialized items onto array at the end.
105 Returns the index of the first uninitialized item added.
106
107 arrdel:
108 void arrdel(T* a, int p);
109 Deletes the element at a[p], moving the rest of the array over.
110
111 arrdeln:
112 void arrdel(T* a, int p, int n);
113 Deletes n elements starting at a[p], moving the rest of the array over.
114
115 arrdelswap:
116 void arrdelswap(T* a, int p);
117 Deletes the element at a[p], replacing it with the element from
118 the end of the array. O(1) performance.
119
120 arrsetlen:
121 void arrsetlen(T* a, int n);
122 Changes the length of the array to n. Allocates uninitialized
123 slots at the end if necessary.
124
125 arrsetcap:
126 size_t arrsetcap(T* a, int n);
127 Sets the length of allocated storage to at least n. It will not
128 change the length of the array.
129
130 arrcap:
131 size_t arrcap(T* a);
132 Returns the number of total elements the array can contain without
133 needing to be reallocated.

135 Hash maps & String hash maps
136
137 Given T is a structure type: struct { TK key; TV value; }. Note that some
138 functions do not require TV value and can have other fields. For string
139 hash maps, TK must be 'char *'.
140
141 Special interface:
142
143
144 stbds_hash_string:
145 size_t stbds_hash_string(char *str, size_t seed);
146 Returns a hash value for a string.
147
148 stbds_hash_bytes:
149 size_t stbds_hash_bytes(void *p, size_t len, size_t seed);
150 These functions hash an arbitrary number of bytes. The function
151 uses a custom hash for 4- and 8-byte data, and a weakened version
152 of SipHash for everything else. On 64-bit platforms you can get
153 specification-compliant SipHash-2-4 on all data by defining
154 STBDS_SIPHASH_2_4, at a significant cost in speed.
155
156 Non-function interface:
157
158 Declare an empty hash map of type T
159 T* foo = NULL;
160
161 Access the i'th entry in a hash table T* foo:
162 foo[i]
163

258 Function interface (actually macros) for strings only:
259
260 sh_new_strdup
261 void sh_new_strdup(T*);
262 Overwrites the existing pointer with a newly allocated
263 string hashmap which will automatically allocate and free
264 each string key using realloc/free
265
266 sh_new_arena
267 void sh_new_arena(T*);
268 Overwrites the existing pointer with a newly allocated
269 string hashmap which will automatically allocate each string
270 key to a string arena. Every string key ever used by this
271 hash table remains in the arena until the arena is freed.
272 Additionally, any key which is deleted and reinserted will
273 be allocated multiple times in the string arena.
274
275NOTES
276
277 * These data structures are realloc'd when they grow, and the macro
278 "functions" write to the provided pointer. This means: (a) the pointer
279 must be an lvalue, and (b) the pointer to the data structure is not
280 stable, and you must maintain it the same as you would a realloc'd
281 pointer. For example, if you pass a pointer to a dynamic array to a
282 function which updates it, the function must return back the new
283 pointer to the caller. This is the price of trying to do this in C.
284
285 * The following are the only functions that are thread-safe on a single data
286 structure, i.e. can be run in multiple threads simultaneously on the same
287 data structure
288 hmlen shlen
289 hmlenu shlenu
290 hmget_ts shget_ts
291 hmgeti_ts shgeti_ts
292 hmgets_ts shgets_ts
293
294 * You iterate over the contents of a dynamic array and a hashmap in exactly
295 the same way, using arrlen/hmlen/shlen:
296
297 for (i=0; i < arrlen(foo); ++i)
298 ... foo[i] ...
299
300 * All operations except arrins/arrdel are O(1) amortized, but individual
301 operations can be slow, so these data structures may not be suitable
302 for real time use. Dynamic arrays double in capacity as needed, so
303 elements are copied an average of once. Hash tables double/halve
304 their size as needed, with appropriate hysteresis to maintain O(1)
305 performance.
306
307NOTES - DYNAMIC ARRAY
308
309 * If you know how long a dynamic array is going to be in advance, you can avoid
310 extra memory allocations by using arrsetlen to allocate it to that length in
311 advance and use foo[n] while filling it out, or arrsetcap to allocate the memory
312 for that length and use arrput/arrpush as normal.
313
314 * Unlike some other versions of the dynamic array, this version should
315 be safe to use with strict-aliasing optimizations.
316
317NOTES - HASH MAP
318
319 * For compilers other than GCC and clang (e.g. Visual Studio), for hmput/hmget/hmdel
320 and variants, the key must be an lvalue (so the macro can take the address of it).
321 Extensions are used that eliminate this requirement if you're using C99 and later
322 in GCC or clang, or if you're using C++ in GCC. But note that this can make your
323 code less portable.
324
325 * To test for presence of a key in a hashmap, just do 'hmgeti(foo,key) >= 0'.
326
327 * The iteration order of your data in the hashmap is determined solely by the
328 order of insertions and deletions. In particular, if you never delete, new
329 keys are always added at the end of the array. This will be consistent
330 across all platforms and versions of the library. However, you should not
331 attempt to serialize the internal hash table, as the hash is not consistent
332 between different platforms, and may change with future versions of the library.
333
334 * Use sh_new_arena() for string hashmaps that you never delete from. Initialize
335 with NULL if you're managing the memory for your strings, or your strings are
336 never freed (at least until the hashmap is freed). Otherwise, use sh_new_strdup().
337 @TODO: make an arena variant that garbage collects the strings with a trivial
338 copy collector into a new arena whenever the table shrinks / rebuilds. Since
339 current arena recommendation is to only use arena if it never deletes, then
340 this can just replace current arena implementation.
341
342 * If adversarial input is a serious concern and you're on a 64-bit platform,
343 enable STBDS_SIPHASH_2_4 (see the 'Compile-time options' section), and ensure
344 values returned by STB_LCG_NEXT function implementation are strong random numbers.
345
346 * The default value for the hash table is stored in foo[-1], so if you
347 use code like 'hmget(T,k)->value = 5' you can accidentally overwrite
348 the value stored by hmdefault if 'k' is not present.
349

531// Inline simplified version of above that only works on character type. Avoids elemsize multiply/divide math and call overhead.
532#define stbds_arrinline_suballoc_char(a, min_capacity) \
533 if (a && stbds_header(a)->inlinealloc) \
534 { \
535 stbds_array_header* h = stbds_header(a); \
536 char* used_end = a + ((h->length + sizeof(size_t) - 1) & ~(sizeof(size_t) - 1)); \
537 char* capacity_end = a + h->capacity; \
538 STB_COMMON_ASSERT(h->length >= 0 && h->capacity >= h->length); \
539 h->capacity = h->length; \
540 if (capacity_end - used_end < sizeof(stbds_array_header) + min_capacity) \
541 { \
542 a = 0; \
543 } \
544 else \
545 { \
546 stbds_array_header* h_suballoc = (stbds_array_header*)used_end; \
547 h_suballoc->length = 0; \
548 h_suballoc->capacity = ((capacity_end - used_end) - sizeof(stbds_array_header)); \
549 h_suballoc->hash_table = 0; \
