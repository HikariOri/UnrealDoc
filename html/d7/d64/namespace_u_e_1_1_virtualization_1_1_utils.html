◆ FixFilterFlags()

EPayloadFilterReason UE::Virtualization::Utils::FixFilterFlags ( FStringView PackagePath,
uint64 SizeOnDisk,
EPayloadFilterReason CurrentFilterFlags )

Adds filter reasons for a package that would only be calculated during the virtualization process and not stored in the payload trailer Currently this is used to fix up reporting in our commandlets and console commands so that it is easier for users to see why payloads have not been virtualized. This is only required because some filters are applied at package save time (when we know the owning asset type) and others at submit time. The two stage filtering does need fixing properly but I am not sure which way we want to do it, this is why we have an experimental utility to fix the reporting as I do not want to commit to an API change while still unsure on the direction we should take.

NOTE: Only works if the "Default" virtualization system is used.

参数
PackagePathUsed to check for EPayloadFilterReason::Path
SizeOnDiskUsed to check for EPayloadFilterReason::MinSize
CurrentFilterFlagsThe filters for the payload stored in the payload trailer.
返回
The final filter reason used by the payload during the virtualization process.

◆ PayloadIdToPath() [2/2]

UE_API void UE::Virtualization::Utils::PayloadIdToPath ( const FIoHash & Id,
FStringBuilderBase & OutPath )

Converts a FIoHash into a file path.

This utility will take an FIoHash and return a file path that is 3 directories deep. The first six characters of the id will be used to create the directory names, with each directory using two characters. The remaining thirty four characters will be used as the file name. Lastly the extension '.payload' will be applied to complete the path/ Example: FIoHash 0139d6d5d477e32dfd2abd3c5bc8ea8507e8eef8 becomes 01/39/d6/d5d477e32dfd2abd3c5bc8ea8507e8eef8.payload'

参数
IdThe payload identifier used to create the file path.
OutPathWill be reset and then assigned the resulting file path. The string builder must have a capacity of at least 52 characters to avoid reallocation.

const FString & ProjectExtension,

Find the project file for the project that contains the provided package file. Note that this only intended to work for package files as it makes several assumptions about the path conventions in order to speed up the search.

@PackagePath Path of a package file to start searching from. The file must be stored under a /content/ directory to be considered valid. @ProjectExtension The extension that the project file may have. @OutProjectFilePath The project path will be written to this string if found. @OutPluginFilePath If the package is stored in a plugin then the path to it's '.uplugin' file will be written to this string.

返回
True if a project file is found otherwise it will return false.
