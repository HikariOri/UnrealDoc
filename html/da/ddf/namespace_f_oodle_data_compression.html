详细描述

Some important rules and guidelines when working with UTexture :

  1. All changes to Texture properties must be wrapped in PreEditChange/PostEditChange , eg :

    Texture->PreEditChange(nullptr); Texture->SRGB = true; Texture->PostEditChange();

    The PostEditChange will automatically UpdateResource when needed, you should generally not call Modify or UpdateResource manually, Pre/PostEdit will do that for you.

    Changes to Texture->Source should be inside a PreEdit/PostEdit in the same way.

    If possible, do all your changes inside a single PreEdit/PostEdit scope.

  2. Before doing anything that relies on a texture having its PlatformData async build finished, you should call

    Texture->BlockOnAnyAsyncChange();

    (use this instead of FinishCompilation or calling to the FTextureCompilingManager directly)

    In some cases you might need to also call WaitForPendingInitOrStreaming.

  3. When creating or filling a texture with new data, call :

    SetModernSettingsForNewOrChangedTexture();

    Basically, do this any time the texture is fresh data and you don't need to try to keep the bits identical to old data because you are hoping to keep patches small. The UTexture default constructor sets things up with legacy values that we don't recommend, they are just that way to avoid unnecessary patches. Whenever posible, use SetModernSettingsForNewOrChangedTexture.

    If a texture is freshly imported, use ApplyDefaultsForNewlyImportedTextures which calls SetModernSettingsForNewOrChangedTexture and also sets up other typical defaults for imported textures.

  4. When possible use the more modern APIs for working with pixel data in UTexture, such as FMipLock and FImage rather than raw arrays of U8. For pixel format conversions, resizes, etc. use FImageCore.

◆ ECompressionLevel

enum class FOodleDataCompression::ECompressionLevel : int8
strong

ECompressionLevel : Choose the Oodle Compression Level this mostly trades encode speed vs compression ratio decode speed is determined by choice of compressor (ECompressor)

If in doubt start with "Normal" (level 4) then move up or down from there

The standard range is in "SuperFast" - "Normal" (levels 1-4)

"HyperFast" levels are for real-time encoding with minimal compression

The "Optimal" levels are much slower to encode, but provide more compression they are intended for offline cooks

representative encode speeds with compression ratio trade off :

Kraken-4 : 1.55:1 , 718.3 enc MB/s Kraken-3 : 1.71:1 , 541.8 enc MB/s Kraken-2 : 1.88:1 , 434.0 enc MB/s Kraken-1 : 2.10:1 , 369.1 enc MB/s Kraken1 : 2.27:1 , 242.6 enc MB/s Kraken2 : 2.32:1 , 157.4 enc MB/s Kraken3 : 2.39:1 , 34.8 enc MB/s Kraken4 : 2.44:1 , 22.4 enc MB/s Kraken5 : 2.55:1 , 10.1 enc MB/s Kraken6 : 2.56:1 , 5.4 enc MB/s Kraken7 : 2.64:1 , 3.7 enc MB/s

ECompressor : Choose the Oodle Compressor this mostly trades decompression speed vs compression ratio encode speed is determined by ECompressionLevel , not the compressor choice.

From fastest to slowest (to decode) : Selkie, Mermaid, Kraken, Leviathan

When in doubt, start with Kraken Representative compression ratios and decode speeds :

Encode provided data with chosen Compressor and Level, using multiple threads for large buffers CompressedBufferSize must be >= CompressedBufferSizeNeeded(UncompressedSize) CompressParallel can be used in all cases instead of Compress it is fast even on small buffers (will just run synchronously on the calling thread) The output made by this function is a single compressed stream of the same format as Compress() can be decoded with either Decompress or DecompressParallel DecompressParallel can only parallelize if CompressIndependentChunks is true at encode time NOTE: CompressIndependentChunks and small MinChunkSize do hurt compression ratio (compared to non-parallel Compress)

参数
OutCompressedDataoutput buffer where compressed data is written; array is appended to
InUncompressedDatainput buffer containing data to compress
UncompressedSizenumber of bytes in InUncompressedData to read
CompressorECompressor to encode with (this is saved in the stream)
LevelECompressionLevel to encode with (this is not saved in the stream)
CompressIndependentChunksshould chunks be made independent (allows for parallel decode)
MinChunkSizeminimum chunk size; making this larger (eg. 16 MB) increases compression ratio but hurts parallelism; only used if CompressIndependentChunks is false
返回
Compressed size written or zero for failure

Calling Compress() or CompressParallel() does not affect whether or not the data can be decoded parallel. That is controlled by CompressIndependentChunks. The choice of Compress vs CompressParallel affects encode speed and compression ratio. CompressParallel lets you sacrifice some compression ratio for faster encodes.

bool CORE_API FOodleDataCompression::DecompressParallel ( void * OutUncompressedData,
int64 UncompressedSize,
const void * InCompressedData,
int64 CompressedSize )

Decode compressed data that was made by Compress, using multiple threads when possible.

UncompressedSize must match exactly the uncompressed size that was used at encode time. No partial decodes.

There's no penalty to using this on small buffers, it will just decode synchronously on the calling thread in that case. DecompressParallel can be used to decode data written by Compress or CompressParallel. DecompressParallel can be used in all places you would call Decompress.

DecompressParallel can only use more than 1 thread if the encoding was done with CompressIndependentChunks = true

参数
OutUncompressedDataoutput buffer where uncompressed data is written
UncompressedSizenumber of bytes to decompress
InCompressedDatainput buffer containing compressed data
CompressedSizesize of the input buffer, must be greater or equal to the number of compressed bytes needed
返回
boolean success
