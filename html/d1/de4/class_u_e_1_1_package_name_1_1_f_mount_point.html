详细描述

The internal implementation of IMountPoint. FMountPoints are present in FLongPackagePathsSingleton.MountPoints while allocated; they are removed from that set, inside a critical section, when their refcount goes to zero.

◆ GetMountOrder()

uint32 UE::PackageName::FMountPoint::GetMountOrder ( ) const
inline

Get/Set the Ephemeral ordering value. MountPoints that have the same RootPath or ContentPath as other mountpoints are selectively returned from queries where they overlap based on higher priority == higher value. Setting higher values higher in priority allows us to easily implement our contract that MountPoints added later are higher in priority than MountPoints added earlier. The exact value of this field can change arbitrarily in MountPoints, when e.g. we reorder the list. Only the relative ordering is guaranteed unchanged for an existing MountPoint.

bool UE::PackageName::FMountPoint::IsMounted ( ) const

Whether the MountPoint is currently mounted. IMountPoints can be registered with PackageName before they are mounted, and IMountPoints will remain allocated, and be used by PackageName rather than replaced with a new allocation when they are mounted, as long as they have a non-zero refcount. Mutable but atomic, can be read from any thread.

void UE::PackageName::FMountPoint::SetMounted ( bool bInMounted,
UE::TWriteScopeLock< FTransactionallySafeRWLock > & ProofOfWriteLock,
const TRefCountPtr< IMountPoint > & ProofOfCallerRefCount,
bool & bOutRemoveFromContainer )

Mark mounted or unmounted. Must only be called within Paths.MountLock, so that the change in value is atomic with external queries about whether a path is mounted. When unmounting, caller must hold a refcount to prevent the possibility of deletion.

Caller should hold exactly 1 refcount when unmounting. In that case bOutRemoveFromContainer will be set to true and we will skip the effort in TryUnregisterAndDelete of removing it from the container.
